# Model card — baseline-ranker Gulder

| | |
|---|---|
| Модель | `baseline-0.1` (взвешенный content score, §8.1) + калибровка confidence Platt (`baseline-0.1+platt`) |
| Rules Engine | `rules-1.0.0` — применяется **до** ранжирования и не зависит от модели |
| Код | `backend/internal/ranking`, веса — `ranking.yaml`; оценка — `backend/internal/eval`, `make eval` |
| Статус | Релиз 1.0. Метрики качества ниже посчитаны на **черновой** разметке — см. «Ограничения» |

## Назначение

Упорядочить букеты, которые Rules Engine уже допустил для конкретного получателя, по соответствию вкусам,
поводу, бюджету и сезону, и объяснить выбор (причины, конфликты, недостающие сведения). Модель **не**
принимает решений о безопасности: исключение по аллергиям, питомцам, астме, запахам и неопознанным
растениям делает Rules Engine, и модель не может его отменить (§7.1, п. 4).

Не предназначена для: медицинских рекомендаций, оценки реальной аллергенности конкретного экземпляра
растения, ранжирования вне каталога магазинов-партнёров.

## Данные

- **Каталог**: демо-каталог `data/` (6 магазинов Алматы, 43 букета, 32 подарка, 35 цветков). Реальный каталог — M7.
- **Справочник растений**: 16 родов из Приложения B TASK.md, построчно сверены с ASPCA 2026-10-20
  ([отчёт](aspca_verification.md)): 15 совпали, гипсофила спорная и оставлена консервативной.
- **Экспертный набор**: `draft-1` — 235 пар «получатель + повод + букет», 48 случаев, 36 получателей
  (аллергии, питомцы, неизвестные поля). Оценки 0–3 выставлены **эвристикой** `cmd/gendraft`
  (любимые цветы и цвета, нелюбимое, бюджет), опасные пары помечены Rules Engine (`is_unsafe=true`, grade 0).
  Проверенная флористом версия `v1` создаётся на экране «Экспертная разметка» (M7).

## Факторы и веса

| Фактор | Вес | Смысл |
|---|---|---|
| flower_match | 0.25 | доля стеблей любимых родов − 0.5 × доля нелюбимых; неизвестно → 0.5 |
| color_match | 0.15 | то же по цветам |
| occasion_fit | 0.20 | таблица «повод → стиль, цвета, формат» + эмоция + формальность |
| style_format | 0.10 | совпадение стиля и формата с профилем |
| budget_fit | 0.15 | 1 в пределах бюджета, линейно ниже min; дороже max — не в Top-5 |
| season_avail | 0.10 | доля стеблей в сезоне на дату повода, 0 если нет в наличии |
| neutrality | 0.05 + 0.05 × неизвестных полей безопасности | без запаха, мало пыльцы, нетоксично (FR-R02) |
| numerology | ≤ 0.15, по умолчанию 0.10 | только если включена дарителем; **в оценке всегда выключена** (FR-N06) |

Confidence = (0.2 + 0.8 × доля известных ключевых полей) × множитель штрафов Rules Engine, затем Platt.

## Метрики

Свежие цифры — в [`eval_report.md`](eval_report.md) (генерируется `make eval`, seed 42, split по получателям 70/30,
bootstrap 1000 по получателям). На `draft-1`:

| Метрика | Значение | Требование |
|---|---|---|
| Unsafe rate (размеченные + Rules Engine по выдаче каталога) | 0 | 0 |
| Нарушения бюджета в наборах ассистента | 0 | 0 |
| Coverage каталога в Top-5 | ≈ 0.44 | ≥ 0.30 |
| ECE baseline → +Platt | ≈ 0.50 → 0.07 | ниже baseline |
| NDCG@5 | ≈ 0.98 | **не интерпретировать**: черновая разметка построена на тех же признаках, что и модель |
| Robustness (−30% полей) | падение ≈ 0.004 | измерить |

## Ограничения

- **Разметка черновая.** NDCG@5 на `draft-1` завышен и проверяет пайплайн, а не качество. Цифры для решения о
  модели появятся после проверки флористом (`v1`, M7).
- **Справочник = граница безопасности.** Нулевой unsafe rate означает «ноль нарушений относительно справочника».
  Справочник сверен с ASPCA, но ASPCA не всеобъемлющ и не даёт степени токсичности; гипсофила требует решения человека.
- **Калибровка** подобрана на маленьком train (≈35 случаев); на черновике confidence почти не связан с релевантностью
  (коэффициент Platt близок к нулю), поэтому калиброванная уверенность почти постоянна.
- **Нумерология** — развлекательная функция без научной основы; влияет на score ≤ 15% и не влияет на безопасность.
- Каталог демо, магазины вымышленные.

## Риски

| Риск | Смягчение |
|---|---|
| Пропуск реального аллергена/токсичности из-за ошибки в справочнике | M7: построчная сверка с ASPCA; property-тесты; консервативное `unknown` |
| Даритель принимает «известных противопоказаний не найдено» за гарантию | Дисклеймер на каждой карточке, запрет «безопасно/гарантированно» в тестах |
| Утечка ответов получателя дарителю | GiverView во всех ответах giver, HTTP-тесты, обобщённые причины |
| LLM предлагает позиции вне каталога или сверх бюджета | Валидация кодом, тесты с LLM-моками (AC-4, AC-5, FR-G02) |
| Смещение к нейтральным вариантам при пустом профиле | Уточняющий вопрос с максимальной ожидаемой пользой (FR-R04) |
