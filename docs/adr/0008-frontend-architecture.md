# 0008. Фронтенд: клиент API, сессия, состояние

- Статус: принято (M5)

## Контекст
§3: React 18 + TypeScript + Vite, react-query, react-hook-form + zod, Leaflet; типы API — только
сгенерированные из `openapi.yaml` (§18.2).

## Решение
- **Клиент API** — `openapi-fetch` поверх типов `openapi-typescript` (`src/api/schema.d.ts`, `make gen-api`).
  Ручных DTO-интерфейсов нет; CI проверяет, что сгенерированный файл совпадает с контрактом.
  `call()` превращает ответ `{"error":{…}}` в `ApiError` с кодом и деталями.
- **Сессия** — access + refresh в `localStorage` (`gulder.session`). Access-токен обновляется заранее,
  за минуту до истечения, поэтому запросы не нужно повторять после 401. Риск XSS принят: CSP и
  отказ от `dangerouslySetInnerHTML`; при необходимости — перенос refresh в httpOnly cookie отдельным ADR.
- **Серверное состояние** — react-query; формы — react-hook-form + zod (вход, повод).
  Профиль — собственный редактор: «не знаю» — отдельная опция, а не пустое поле (AC-2, §13).
- **Карта** — react-leaflet 4 (совместим с React 18) + тайлы OSM, загружается лениво. Геолокация
  запрашивается только по клику «Рядом» и живёт только в состоянии страницы (FR-L01).
- **Тексты** — русские; тест запрещает «безопасно/гарантированно» в коде UI (и аналогичный тест в Go — в сообщениях API).

## Следствия
- e2e (Playwright) идёт по реальному API и БД: `webServer` поднимает миграции, сид, API и Vite,
  либо работает с уже поднятым compose-стеком (`E2E_BASE_URL`, так в CI).
- Компонентные тесты (vitest + Testing Library) подменяют `fetch`; клиент берёт `fetch` в момент запроса.
