# 0010. Развёртывание и эксплуатация

- Статус: принято (M8)

## Контекст
§18.6: один хост, docker compose + reverse proxy с TLS (Caddy) либо fly.io; миграции — отдельным шагом;
`pg_dump` по расписанию с хранением вне хоста и проверенным восстановлением. §18.4–18.5: метрики, rate limiting.

## Решение
- **Один хост, Docker Compose** (`docker-compose.prod.yml`): `postgres` (порт не публикуется), `backend`
  (API :8080 и `/metrics` :9090 только внутри сети), `web` — Caddy со статикой фронтенда, reverse proxy `/api` и
  автоматическим TLS для `$DOMAIN`. fly.io отклонён: Postgres и бэкапы проще держать под своим контролем.
- **Миграции** — сервис `migrate` в профиле `migrate`, запускается явно перед `up` новой версии; API их не применяет.
- **Заголовки** в Caddy: HSTS, nosniff, Referrer-Policy, Permissions-Policy (геолокация только своя), CSP
  (тайлы OSM и изображения GBIF разрешены, `style-src 'unsafe-inline'` нужен Leaflet).
- **Бэкапы** — `scripts/backup.sh` из cron хоста: `pg_dump -Fc`, проверка `pg_restore --list`, SHA-256, `rclone` вне хоста,
  ротация. **Восстановление** — `scripts/restore.sh` только в пустую базу, со сверкой счётчиков; каждая проверка
  записывается в журнал в runbook.
- **Метрики** — собственный реестр Prometheus; метки только шаблоны маршрутов и коды, без персональных данных (тест).
- **Rate limiting** — `go-chi/httprate`: `/auth/*` по IP, `/recommendations` и `/gift-sets` по пользователю (стоимость LLM),
  `/public/invites/*` по токену; ответ 429 в формате ошибок API. IP клиента берётся из `X-Forwarded-For` **только**
  если запрос пришёл от доверенного прокси (`TRUSTED_PROXIES`, в проде — сеть compose с Caddy): иначе заголовок
  подделывается, и лимит можно обойти или «выжечь» чужой IP (`KeyByRealIP` из httprate отклонён по этой причине).

## Следствия
- Без `BACKUP_REMOTE` бэкап остаётся на хосте — скрипт предупреждает; хранение вне хоста нужно настроить при развёртывании.
- Масштабирование за пределы одного хоста (несколько реплик API) потребует общего хранилища лимитов (Redis) — пока не нужно.
