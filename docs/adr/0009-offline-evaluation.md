# 0009. Офлайн-оценка: методика и черновая разметка

- Статус: принято (M6)

## Контекст
§11 требует NDCG@5 с 95% CI, unsafe rate 0, нарушения бюджета 0, coverage, ECE, robustness, split по получателям
и воспроизводимость по seed. Настоящей экспертной разметки пока нет (§12: сначала черновик, проверка — M7).

## Решение
- **Черновик** `draft-1` генерирует `cmd/gendraft` (детерминированно по seed): 36 получателей, 48 случаев, 235 пар;
  на случай — букеты по любимым цветам/цветам, один заведомо опасный, остальные допустимые в бюджете.
  Оценка — эвристика, опасность — Rules Engine. В отчёте и model card явно сказано, что NDCG на черновике не
  интерпретируется.
- **Split** по получателю: хэш(seed, ключ получателя) < 0.3 → test. Один получатель не попадает в обе части (тест).
- **NDCG@5** — по размеченным букетам случая в порядке модели (дороже бюджета не выдаются), выигрыш 2^g − 1;
  CI — bootstrap 1000 по получателям (среднее по случаям получателя), фиксированный seed.
- **Unsafe**: (а) доля размеченных `is_unsafe` в выдаче; (б) Rules Engine на эталонном профиле по Top-5 всего каталога.
- **Бюджет**: ассистент (fallback, без сети) на бюджете случая; считаем наборы с суммой > бюджета.
- **ECE**: confidence выданных позиций против «grade ≥ 2», 10 бинов. «Модель» для сравнения в 1.0 —
  baseline + калибровка Platt, подобранная на train; P1-модель (learning-to-rank, §8.4) добавится вторым запуском на том же split.
- **Robustness**: каждое поле профиля с вероятностью 0.3 становится неизвестным, 5 повторов, падение NDCG@5.
- Каждый запуск пишет две строки `research.experiment_runs` (baseline и +platt) с одним `split_id` и параметрами (RM-04)
  и `docs/eval_report.md`. Часы оценки фиксированы (`2026-11-01 12:00 ALMT`), чтобы скидки и сезонность не плавали.

## Следствия
Метрики качества станут осмысленными только после `v1`. Пайплайн, пороги безопасности и воспроизводимость
проверены уже сейчас (`TestAC9_EvaluationPipeline`).
