# 0003. База для интеграционных тестов

- Статус: принято (M0)

## Контекст
§3 требует testcontainers-go. На машине разработчика Docker может отсутствовать, а CI
должен проверять SQL на настоящем PostgreSQL 16.

## Решение
`internal/testdb.New(t)`:
1. если задан `TEST_DATABASE_URL` — на этом сервере создаётся отдельная база на тест и удаляется после;
2. иначе поднимается `postgres:16-alpine` через testcontainers (один контейнер на пакет);
3. если Docker недоступен — тест пропускается (`t.Skip`) с понятным сообщением.

В CI задан `TEST_DATABASE_URL` на сервис-контейнер GitHub Actions — интеграционные тесты не пропускаются.

## Альтернативы
- Только testcontainers: локально без Docker тесты не запускаются вовсе.
- Моки БД: не ловят ошибки в SQL, CHECK и триггерах.

## Следствия
- `go test -short` пропускает интеграционные тесты.
- Каждая база проходит все миграции, поэтому тесты заодно проверяют `Up`.
