# 0001. Доступ к БД: чистый pgx без sqlc

- Статус: принято (M0)

## Контекст
§3 допускает `pgx/v5 + sqlc` или чистый pgx. Запросов немного, часть из них — динамические
(фильтры, импорт с upsert), схема ещё будет меняться миграциями.

## Решение
Чистый `pgx/v5` (`pgxpool`). `internal/store` содержит пул, транзакции (`InTx`) и миграции goose
(встроены в бинарник через `embed`). Запросы живут рядом с логикой в пакетах фич
(`catalog`, `recipients`, …), а не в одном «god»-пакете.

## Альтернативы
- sqlc: типобезопасность запросов, но лишний генератор в цепочке сборки и CI, а динамические
  запросы всё равно пришлось бы писать руками.
- ORM (gorm, ent): скрывает SQL, плохо сочетается с CHECK/триггерами из Приложения A.

## Следствия
- Ошибки в SQL ловятся интеграционными тестами (testcontainers / `TEST_DATABASE_URL`), а не компилятором.
- Миграции — отдельная команда `cmd/migrate`, API их не применяет (§18.6).
